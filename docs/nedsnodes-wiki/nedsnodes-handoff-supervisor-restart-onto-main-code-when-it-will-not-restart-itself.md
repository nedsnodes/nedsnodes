# Restarting a handoff-supervisor onto main's code when it will not restart itself

A running handoff-supervisor keeps the code it started with, because its process reads its Python code once, when it starts. At each session-handoff that launches a successor without consulting the user, the handoff-supervisor restarts itself on main's code, as the handoff-system's nn-architecture-overview, `docs/nedsnodes-wiki/nedsnodes-handoff-architecture-overview.md`, says.

The restart program, `python3 ~/Projects/nedsnodes/nn-systems/handoff/handoff-supervisor-restart-onto-main-code-by-relaunch-from-reference-checkout.py <seat>`, is for a handoff-supervisor that is running and will not restart itself: one whose code predates that restart; one that runs from a checkout other than the reference-checkout `~/Projects/nedsnodes`, such as the handoff-supervisor of a Mac agent-seat started from its agent-home by a `launch-claude-mac` that predates the `--supervisor-checkout` option, or one started with that option naming another checkout, since the handoff-supervisor's own restart fast-forwards the checkout it runs from and fails whenever that checkout cannot be fast-forwarded to main, as when it holds commits main lacks; or one whose own restart failed for a reason other than its checkout. The agent-seat being restarted runs the program itself, on the machine it runs on; an agent-seat on ned-box runs it through `ssh nedlern@ned-box '<command>'`, because the Bash sandbox cannot signal the handoff-supervisor. The program's docstring says what the agent-seat does before and after running it, what the program does, how each failure leaves the agent-seat, and what it cannot handle.

When neither a handoff-supervisor nor an agent-session of the agent-seat runs, the restart program does not apply: `scripts/recover-crashed-seats.py`, which brings back an agent-seat whose handoff-supervisor is gone, is the tool for that agent-seat.

When an agent-session of the agent-seat runs but no handoff-supervisor watches it, neither the restart program nor `scripts/recover-crashed-seats.py` applies: the agent-session writes its session-handoff at once, by the /handoff skill, and tells the user, who then runs, on the Mac, `python3 ~/Projects/nedsnodes/scripts/resupervise-seat.py <seat> --machine <machine>`, with `ubuntu` for an agent-seat on ned-box and `mac` for one on the Mac. That program ends the agent-session, losing anything done after the session-handoff was written, and starts a successor from that session-handoff under a new handoff-supervisor.

When the reference-checkout cannot be fast-forwarded to main at a session-handoff, a handoff-supervisor running from the reference-checkout runs `nn-systems/handoff/handoff-reference-checkout-back-on-main-after-pushing-leftovers-to-a-branch.py` on its own, and restarts when that program succeeds. When that program fails, the successor's initial-agent-instructions say the handoff-supervisor did not restart, quote what the program printed, and say what the agent-seat does next, with the command to run. Do what that notice says, and do not run the restart program for that notice: the restart program pushes no leftovers, and its first step fails whenever the checkout will not fast-forward.
