# Fix the problems the cold reads found in the unchanged text of the cold-read prompts under `.claude/skills/cold-read/prompts/`

## What this is

The three prompts under `.claude/skills/cold-read/prompts/` tell the cold-read-cells what to do: `fast-clarify-prompt.md` for the cold-read-cell of every cold-read-fast-read, and `defect-hunt-prompt.md` and `terminology-prompt.md` for the cold-read-cells of a cold-read-full-run. `nn-systems/cold-read/cold-read-fast-read.py` holds a copy of the fast-clarify prompt as `FAST_CLARIFY_PROMPT_TEMPLATE`, which a test in `nn-systems/cold-read/tests/cold-read-fast-read-test.py` keeps identical to the file, so every change to that prompt is made in both. The program also finds the words held in `FAST_CLARIFY_PROMPT_DOCUMENT_READING_RULES_OPENING_WORDS` and `FAST_CLARIFY_PROMPT_DOCUMENT_READING_RULES_CLOSING_WORDS` inside the template, so a change to those words changes those constants too.

Pull request [cold-read-fast-read: --text-intended-reader-category names the reader the text is written for, and callers that know it pass it](https://github.com/nedsnodes/nedsnodes/pull/4108) edits the fast-clarify prompt. Its cold-read-full-run, and the cold-read-fast-reads before and after it, found about 150 real problems in text that pull request does not change. Pull request [Cold-read defect-hunt and terminology prompts say agent-binary, not runtime](https://github.com/nedsnodes/nedsnodes/pull/4117), which changes "runtime" to agent-binary in the other two prompts, gave each of them a cold-read-fast-read, and those found about 40 more in text it does not change. Under step 8 of the /cold-read skill such problems are deferred, not declined; the prompts have no open questions and no section headed `Deferred-decisions` to hold them, so this GHI holds them. When this GHI-MD was written, pull request 4108 was an open draft pull request at nn-head-commit e0ceac2fe, and its findings quote the fast-clarify prompt as that pull request leaves it, not as main has it.

## Why

Each finding names a case in which a cold-read-cell cannot tell what its prompt wants, or in which two sentences of a prompt pull different ways. The fast-clarify prompt runs on every cold-read-fast-read in the project and the other two on every cold-read-full-run, so an unclear instruction in them makes reports that differ from one read to the next, or miss the defects the read is for.

## Next action

Changing what a prompt tells the reader to do needs the user's approval. The agent-seat that takes this GHI waits until pull request 4108 has merged or closed, rereads each finding against the prompts as main then has them, whether or not 4108 merged, and drops those the text on main has settled. It then puts the rest to the user in one approval-walk, its items grouped by the topics above, all of group 3 included except the hop count, which GHI 284's rule settles; the code work of groups 12 to 14 goes to GHI 2158 instead. It makes every approved change to the prompts in one pull request, carrying each change to the fast-clarify prompt into `FAST_CLARIFY_PROMPT_TEMPLATE` and into the two constants named above when their words change. It then records the user's rulings, the declined findings with them, in this GHI-MD with edit-GHI, which opens a pull request of its own.
