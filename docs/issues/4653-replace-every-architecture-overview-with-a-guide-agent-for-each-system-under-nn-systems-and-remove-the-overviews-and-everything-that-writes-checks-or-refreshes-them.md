# Replace every architecture overview with a guide-agent for each system under `nn-systems/`, and remove the overviews and everything that writes, checks or refreshes them

The user decided that the project's architecture overviews go, with all the machinery that writes, checks and refreshes them, and that a guide-agent for each system, or for each big subsystem, answers agents' questions about the system in their place. A guide-agent, as `docs/nedsnodes-wiki/nedsnodes-glossary.md` defines it, keeps reading its system's current files, so its answers come from the files, which stay the single source of truth, rather than from a summary that drifts from them. This GHI owns both halves of that work: removing the overviews and their machinery, and the guide-agents that replace them. It is not yet a design. ned-box-helper writes the design, which names the open questions below for the user to decide.

GHI [Two more guide-agents: wiki-guide-agent for the wiki, and agent-instructions-and-hooks-guide-agent for how the project instructs and controls its agents](https://github.com/nedsnodes/nedsnodes/issues/2266) is related: it designs two guide-agents on the pattern of ghi-guide-agent, for the wiki and for how the project instructs its agents, and covers no system under `nn-systems/`. A search of the GHIs found no open GHI that covers this subject (ghi-guide-agent, asked on 2026-11-24 with `--include-closed`, read GHIs 670, 2205, 2532, 3418, 3544, 130, 2709, 3950, 26, 2266, 46 and 168, and answered that no open or closed GHI proposes it).

## What this GHI adds

A guide-agent for each system under `nn-systems/`, or for each big subsystem, and possibly one for the approval-walk or for a collection of user-interface material, as the user's words above allow. Each guide-agent keeps reading its system's current files, answers other agents' questions about the system, and looks further into the files when a question needs more. The pattern to reuse is ghi-guide-agent, GHI [Build ghi-guide-agent — the GHI knowledge agent](https://github.com/nedsnodes/nedsnodes/issues/46), designed in `docs/issues/46-ghi-guide-agent.system.design.md`, and the two guide-agents GHI 2266 designs on that pattern. In that pattern a program, the ask script, does the steps that need no judgment, such as bringing the guide-agent's checkout up to main before each question (`docs/issues/46-ghi-guide-agent.system.design.md` § The ask path (ghi-guide-agent-ask)) and checking that each citation in a reply exists (GHI-MD 2266, § The reply, and how code validates it); the design names which steps of a system's guide-agent need judgment, as `CLAUDE.md` requires of every design.

The user named "guide-book" on 2026-11-24 for what a guide-agent is given besides its system's files: what the files leave unexplained, such as why the system exists (ned-box-helper's walk-minutes `nedlern@ned-box:/home/nedlern/agents/ned-box-helper/docs/walk/ned-box-helper-open-items-approval-walk-2026-11-22-minutes.md`, line 137, relaying item 24 of overall-cleanup's approval-walk overall-cleanup-items-handed-over-from-long-approval-walks-2026-11-21). No glossary defines guide-book yet: the item "The glossary entry for guide-book" of ned-box-helper's approval-walk ned-box-helper-open-items-approval-walk-2026-11-22 (walk-document `nedlern@ned-box:/home/nedlern/agents/ned-box-helper/docs/walk/ned-box-helper-open-items-approval-walk-2026-11-22.md`, line 2332) brings him the entry's wording, and what a guide-book holds is open question 2 below.

## Open questions for the design

The design names each of these, with options, for the user to decide; this GHI decides none of them.

1. How systems are grouped under guide-agents: one guide-agent for each directory under `nn-systems/`, one for each big subsystem, one for the approval-walk, one for user-interface material, or some mix; and how an asking agent finds the guide-agent that covers a path, such as by a table a program reads.
2. Which guide-agent, if any, answers questions that span systems, which the project-wide page `docs/nedsnodes-wiki/nedsnodes-project-architecture-overview.md` was meant to answer.
3. What a guide-book holds, where it is kept, how it is kept in line with its system's files, and how the user reviews its changes. The item "Write the design that removes every architecture overview and gives each guide-agent a guide-book" of ned-box-helper's approval-walk ned-box-helper-open-items-approval-walk-2026-11-22 (same walk-document, line 2243) proposes answers to these and to questions 4 and 6; the user has not answered that item.
4. Whether a system gets its guide-agent before its overview is removed, or only when someone first needs one; in the second case, a system can for a while have neither, and an agent changing it reads its code and design.
5. Which agent-seat builds and maintains each guide-agent, and which makes each removal. The glossary says a guide-agent is not an agent-seat, so it is run by a script, and some agent-seat changes that script and the guide-agent's prompt; the design proposes each such owner agent-seat for the user's approval.
6. What happens to the open GHIs and pull requests that build on the overviews: GHIs [130](https://github.com/nedsnodes/nedsnodes/issues/130), [2205](https://github.com/nedsnodes/nedsnodes/issues/2205), [2532](https://github.com/nedsnodes/nedsnodes/issues/2532), [3418](https://github.com/nedsnodes/nedsnodes/issues/3418) and [3544](https://github.com/nedsnodes/nedsnodes/issues/3544), and pull requests such as [3965](https://github.com/nedsnodes/nedsnodes/pull/3965) and [4487](https://github.com/nedsnodes/nedsnodes/pull/4487), all open on 2026-11-24.
7. The order of the work: whether the removal is one pull request ahead of any guide-agent.
