# Merge queue: when the stop file cannot be written on the dead-batch path, `merge-batch-start` exits 0 and says the stop file was written, in `scripts/merge-lane-merge-queue-approved-lines-merge-in-order-until-none-left.py`

## Reproduction

The reproduction program `nedlern@ned-box:/home/nedlern/nedsnodes-logs/seats/merge-lane-1/merge-batch-start-findings-reproduce-2026-11-26/merge-batch-start-findings-reproduce.py` takes the path of a checkout as its one argument and runs that checkout's merge queue program, `scripts/merge-lane-merge-queue-approved-lines-merge-in-order-until-none-left.py`, in a fresh temporary directory, with a fake `gh`, a fake merge program and a fake follow-up program, so it reads and writes nothing on GitHub or under `/home/nedlern/nedsnodes-logs/seats/merge-lane-2/`. Its case "feb1e7dc001a", named by the id of the Codex review cell's finding it tests, from merge-lane-1's review 6068181614 of PR [Merge queue checks the stop and in-progress files at every entry, passes its outputs directory both ways, and keeps each outcome where it happens](https://github.com/nedsnodes/nedsnodes/pull/4955), leaves `merge-batch-merge-in-progress.txt` in the merge batches directory, as a batch that died during a merge leaves it, makes the merge program's outputs directory, which holds the stop file, unwritable with `chmod 555`, and runs `merge-batch-start`. Its outputs are `reproduce-output-origin-main-157731f5a914.txt` and `reproduce-output-origin-main-5b3c85e2b80e.txt` beside it.

- On origin/main `157731f5a914`, with that pull request merged: `merge-batch-start` exits 0 and prints `DIED MID-MERGE: ... The stop file and a stopped notice in ... now say so`. The stop-file write failed with `[Errno 13] Permission denied`, which only the stopped notice and the merge queue program's own log line say. The in-progress file is kept, so a second `merge-batch-start` prints `DIED MID-MERGE` again and starts nothing.
- On origin/main `5b3c85e2b80e`, before that pull request: the same exit 0 and the same line, and `stopped()` also removed the in-progress file, so the second `merge-batch-start` printed `STARTED` and its batch merged pull request 1 onto the main the dead merge left unchecked. That pull request fixed this second part by keeping the in-progress file when the stop file is missing.

## What is wrong

The module docstring says exit 1 means "a file or GitHub could not be read or written", and the merge-lane-2 seat-brief, `/home/nedlern/agents/merge-lane-2/CLAUDE.local.md`, treats a step that can fail while the code reports success as one to fix. `start()` prints its `DIED MID-MERGE` line, which says the stop file was written, before `died_mid_merge_stopped()` tries to write it, and returns 0 whatever `stopped()` met. The root cause is in `stopped()`: it only adds a failed stop-file write to the reason in the notice, and only logs a failed notice write, so none of its callers can tell. Read from the code and not reproduced, the same holds for each other caller: `run_in_queue_order()` returns 0 after `died_mid_merge_stopped()`, after the outside-stop path's `stopped(..., write_stop_file=False)`, and after `except Stop`, such as a merge program that exited 3 or 4. A caller that reads the exit code or the printed line, and not the notice, believes the queue is stopped by the stop file when only the kept in-progress file stops it; the merge program, which reads the stop file and not the in-progress file, would then merge if run by hand.

## What to do

No record shows the write failing, and the merge queue program is not in live use yet: on 2026-11-26 ned-box had no directory `/home/nedlern/nedsnodes-logs/seats/merge-lane-2/merge-queue-merge-batches`, its default merge batches directory. The agent-seat overall-cleanup, which wrote this code in PR [Merge queue program merges approved lines in order until none is left](https://github.com/nedsnodes/nedsnodes/pull/4893), fixes the root cause: have `stopped()` return which of its writes failed, and have every caller exit 1 when the stop file or the notice could not be written. `start()` prints its line from what was written, for example an outcome state of its own for an unwritten stop file or notice, listed in the module docstring's outcome table, so merge-lane-2 branches on the line's first word. Add a test case to `scripts/merge-lane-merge-queue-approved-lines-merge-in-order-until-none-left-test.py` for each caller, making the stop-file write fail as the reproduction does, and making the notice write fail by making the notice directory unwritable.
