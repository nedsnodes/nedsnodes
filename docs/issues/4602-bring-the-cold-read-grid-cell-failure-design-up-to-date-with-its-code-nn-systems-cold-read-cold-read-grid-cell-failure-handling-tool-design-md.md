# Bring the cold-read-grid's cell-failure design up to date with its code: `nn-systems/cold-read/cold-read-grid-cell-failure-handling.tool.design.md`

## What is wrong

`nn-systems/cold-read/cold-read-grid-cell-failure-handling.tool.design.md` is the design of how `nn-systems/cold-read/cold-read-grid.py` retries a cold-read-cell that ends without a report, names the cause of each failed attempt, and closes every cold-read-full-run with one closing text. Its introduction says "What this document describes is now what the code does". That is no longer true: the code has changed since the design was last brought up to date, and the design was never changed to match.

On 2026-11-24 a cold-read-full-run read the design as pull request [Remove the cold-read account-limit failure cause ("You've hit your ... limit")](https://github.com/nedsnodes/nedsnodes/pull/4596) changes it. Its triage, `nedlern@ned-box:/home/nedlern/nedsnodes-logs/cold-read-records/cold-read-grid-cell-failure-handling.tool.design-2026-11-24-2/cold-read-triage.md`, labelled 16 groups of findings FN1 to FN16 and sorted them as fix-next, the triage's word for real defects in text that pull request 4596 does not change, to be fixed in one later change. This GHI holds them. The reports are in the same log-store directory on ned-box, and each is named here by its abbreviation in that triage: CHD is `claude-hunt-deep.md`, CH2 `claude-hunt-second-strongest-model.md`, XHD `codex-hunt-deep.md`, XH2 `codex-hunt-second-strongest-model.md`, AGY `agy-hunt-gemini-4-neon-high.md`, XT `codex-terminology-deep.md`, CT `claude-terminology-deep.md` and Q4 `question-4-what-should-be-code-answer.md`; a number after the abbreviation is a finding's number in that report. FR names the cold-read-fast-read `nedlern@ned-box:/home/nedlern/nedsnodes-logs/cold-read-records/cold-read-grid-cell-failure-handling.tool.design-2026-11-24/cold-read-fast-read.md`, and a Q number after FR is a finding's question number in it.

Each defect below was checked against the design and the code on main at commit `006829f48` on 2026-11-24, and against the head of pull request 4596, commit `c5bd4ce35`. Left out: section 4's sentence that counts the cause classes ("The first two … The next three … and the last two"), which waits on the user's decision in an approval-walk of the cold-read-improvement agent-seat, and is carried out there, not here; and every passage pull request 4596 changes or will change before it merges, which includes everything about the `account-limit` class and the triage's must-fix-now items MF1 and MF3, which belong to that pull request's own topic whether it merges or closes. Where pull request 4596 rewrites a line but keeps a defect in it, the defect is listed.

Why it matters: the design is the specification of the code and of the tests that bind it, and the /cold-read skill's steps 6 and 7 tell agents what the cold-read-grid's lines mean. An agent that trusts the design about exit codes, retries or which lines it will see acts on behavior the code does not have.
