# Handoff-system: record each detached headless job in a file the session-handoff writer reads

This proposal, not yet decided, is item 1 of Question 4, "What should be code", of the cold-read-full-run of `nn-systems/handoff/handoff.system.design.md` on 2026-11-20: `nedlern@ned-box:/home/nedlern/nedsnodes-logs/cold-read-records/handoff.system.design-2026-11-20-6/question-4-what-should-be-code-answer.md`. The queue-drain decides it: if promoted, it becomes a GHI of its own; if declined, this file is removed with the reason in the commit message.

The design tells the agent that starts a detached headless agent-session to name the job, its session id, where its output goes and its costs in the next step of its next session-handoff, because otherwise the successor is not told the job exists. A launcher for such jobs could append the job, session id and output path to a file kept for each agent-seat, and the writer, `nn-systems/handoff/handoff-write-and-check-supervisor.py`, could copy that file into numbered fields like its `background-task-N` fields. Nearest: GHI [run-agent: one CLI to invoke a Claude or Codex agent headlessly from any caller (Python, shell, either runtime)](https://github.com/nedsnodes/nedsnodes/issues/41), the launcher such a record would extend.
