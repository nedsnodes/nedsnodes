# Agent-seat temp folders: one root on each machine, and a daily job that deletes what has not changed for 7 days: design

Status: approved, with the decisions in § 11; not built.

## 1. The problem

Five programs and rules clean up leftovers today, each with its own keep-rules (§ 6 says what each does). Even so, no job cleans merge-lane-2's merge-helpers folder in the log-store, `nedlern@ned-box:/home/nedlern/nedsnodes-logs/seats/merge-lane-2/merge-helpers`, which held 55 GB on 2026-11-17, and the log-store is in ned-box's hourly Timeshift backup. Each new keep-rule adds code and tests for a case that may never happen, as [pull request 3219](https://github.com/nedsnodes/nedsnodes/pull/3219) did before it was closed.

This design replaces the keep-rules for the temporary things § 4 lists with one rule: a program puts each temporary thing in its own folder under one root, and a daily job deletes any such folder in which nothing has changed for 7 days, unless the deletion fails (§ 3). `/tmp` keeps its own rule (§ 6). Worktrees that hold an agent-seat's own branch are not temporary: they stay outside the root, and `scripts/clean-worktrees.py`, the cleaner, removes them by the rules § 7 keeps.

## 2. The root and its layout

The root on each machine is `~/.cache/nedsnodes-temp-folders-by-agent-seat/` (§ 11, decision 1). Only ned-box uses it at first (§ 9).

Layout: `<root>/<agent-seat>/<temp folder>/`. The agent-seat is the one whose program makes the folder. A program that belongs to one agent-seat names it: the merge-lane programs § 4 lists name merge-lane-2, so their folders go under `<root>/merge-lane-2/` whichever agent-session or cron job runs them. Any other program leaves the agent-seat to the shared function below, which reads it from `NEDSNODES_HANDOFF_SUPERVISOR_AGENT_NAME`, the environment variable the handoff-supervisor sets for every agent-session it starts (named in `nn-systems/handoff/handoff-supervisor-launched-agent-session-environment-variable-names-common.py`), and uses `no-agent-seat` when that variable is unset or empty, as for a program started outside any agent-session.

A temp folder is one entry directly inside `<root>/<agent-seat>/`. It is the unit the daily job judges and deletes. A program that makes temporary things makes one temp folder for each piece of work, such as the review worktrees of one pull request, so that the folder stops changing once that work stops, because a folder that something writes into every day is never deleted. The review tools worktree in § 4 is the one temp folder that serves many pieces of work. One shared function, in `nn-systems/general-tools/agent-seat-temp-folder-create-common.py`, takes a name and, optionally, the agent-seat; refuses a name that is empty, is `.` or `..`, or holds `/`, a tab, a newline or another control character, since the daily job's log keeps one entry to a line; and returns the path `<root>/<agent-seat>/<name>`. It creates nothing. The caller makes the folder with its parent folders, as `git worktree add` and `mkdir -p` do, because the daily job removes an empty `<root>/<agent-seat>/`.

## 3. The daily job

`nn-systems/general-tools/agent-seat-temp-folders-unchanged-seven-days-delete.py` runs once a day on ned-box at 07:30, the slot of the job it replaces (§ 6), installed from `nn-systems/general-tools/scheduled-jobs-on-each-machine.json`, the table of scheduled jobs. It needs no judgment. For each entry directly inside each `<root>/<agent-seat>/`, folder or file alike, it:

1. Reads the entry's newest change time: the latest of the modification time and the status-change time (mtime and ctime) of the entry and, for a folder, of every entry under it at any depth, read with lstat, never following a symbolic link. The status-change time counts because `mv` and `cp -p` keep an old modification time on a file they have just put there, while the status-change time of a folder moved into the root becomes the time of the move, as a test on ned-box's btrfs filesystem showed on 2026-11-17. So a folder moved into the root is not deleted on the next day for its contents' age.
2. Keeps the entry when that time is less than 7 × 24 hours before the job's start, or in the future.
3. Otherwise deletes it. When the entry is a folder holding a `.git` file, it is a git worktree: the job runs `git worktree remove --force` on it in the repository the `.git` file names, so that git's registration goes with it. A registration left behind would make the next `git worktree add` at that path fail, as merge-lane-2's `scripts/merge-lane-pull-request-head-and-merged-worktrees-rebuild.py` does for a pull request reviewed again. Any other entry is deleted with its contents. A worktree nested deeper inside a deleted folder leaves a registration behind, which the cleaner's line for registrations whose folder is gone reports; a later `git worktree add` at that same path fails with git's message naming the registration, which `git worktree prune` clears.
4. Removes `<root>/<agent-seat>/` when it is empty after this run's deletions.

Before each deletion it prints `deleting <entry>`, flushed, and appends `<UTC time><tab>deleting<tab><entry>` to the local file `/home/nedlern/nedsnodes-logs/agent-seat-temp-folders-deleted-log/<machine>.txt` in the log-store, so the log names every entry a run stopped part way may have deleted; when the deletion then fails, it appends `<UTC time><tab>failed<tab><entry>`. When an append fails, the job deletes nothing more, names the failure on stderr and exits 1. `--dry-run` prints `would delete` for each entry it would delete, deletes nothing and appends nothing to the log. An entry whose tree cannot be read in full is kept. An entry whose `git worktree remove` is refused, such as a locked worktree, is kept whole; one whose deletion fails part way is left as the failure left it. Each is named on a line on stderr, and the job goes on to the others and exits 1. No user-alert is written.

What the job does not handle: a running process or a bound socket inside a temp folder in which nothing has changed for 7 days. The folder is deleted. The program that lost its folder makes a new one, or fails with an error that names the missing path, and its work is done again.

On 2026-11-17 a search of `merge-helpers/hr/` and `merge-helpers/rv` alone found 28 files, such as the test logs [GHI 1233](https://github.com/nedsnodes/nedsnodes/issues/1233) cites under `hr/pr<n>/tmp/` and the file [GHI 3096](https://github.com/nedsnodes/nedsnodes/issues/3096) cites under `rv1289r1-dead-reviewer-2352/`. Citations that name a pattern rather than a file, such as [GHI 2569](https://github.com/nedsnodes/nedsnodes/issues/2569)'s `hr/pr*/stderr` and [GHI 1374](https://github.com/nedsnodes/nedsnodes/issues/1374)'s `hr/*/log-store/...`, describe measurements already made, and stop opening anything once the folders are deleted; the one-off move copies none of the files they match (§ 11, decision 3). The same program moves every entry of `~/.cache/merge-lane-review-worktrees/` and of `~/.cache/merge-lane-pull-request-reviewer-scratch-directories/` into `<root>/merge-lane-2/`, under the names § 4 gives and any other entry under its own name, a worktree with `git worktree move`, so that nothing is left in the old places once the jobs and rules that cleaned them are gone, and removes each old directory once it is empty. A moved folder gets a new status-change time, so the daily job deletes it at its first run at least 7 days after the move, not on the next day.

## 7. clean-worktrees.py, cut down

Worktrees that hold an agent-seat's own branch stay where they are. The cleaner keeps its two removal rules that judge a worktree by its owner and its branch's pull request: a worktree whose branch's pull request has merged or closed, and a worktree whose owner has stopped and that has no open pull request (§ 11, decision 4). It loses the rules that judge a worktree by its age and the rule for merge-lane review checkouts. Every duty that keeps a removal from losing work that cannot be done again stays.

| Duty today | Kept or cut | Why |
|---|---|---|
| Remove a worktree whose branch's pull request has merged or closed | kept | The rule the cleaner has today. Every removal still passes the checks the cleaner makes today, such as the lock, in-progress operation and vacancy checks. |
| Remove a worktree whose owner has stopped and that has no open pull request | kept | § 11, decision 4. Between 2026-11-04 and 2026-11-17 this rule removed 171 worktrees whose branch never had a pull request; 143 of the 171 were Claude Code subagent worktrees under the reference-checkout's `.claude/worktrees/`, and 93 of the 171 were removed at a session-handoff. |
| Remove an idle worktree: unchanged 2 days, nothing uncommitted, every commit on origin | cut | It judges a worktree by its age, which the root now does for temporary things; a worktree with nothing to lose that this rule no longer removes is shown to its agent-seat by the first-prompt list, `nn-systems/handoff/agent-seat-worktrees-and-branches-with-no-pull-request-first-prompt-list.py`, when its owner file names that agent-seat; one with no owner file, such as a worktree made by hand, stays until someone removes it, and the cleaner's count line counts it. |
| Remove a merge-lane review checkout 24 hours after its pull request finished | cut | Review checkouts move into the root (§ 4); the merge program already removes `pr<n>-head` and `pr<n>-merged` after a merge, and the daily job removes the rest. |
| Ship walks, cold-read-records and sanity-check records before a removal, keeping the worktree when one does not ship | kept | A record not in the log-store would be lost for good. No record was ever shipped from a review checkout, so review checkouts need no shipping in the root. |
| A work-snapshot of uncommitted files, and a branch for commits on a detached HEAD, before a removal | kept | The files and commits cannot be made again; one work-snapshot has been restored, by the task it opened under `~/.claude/tasks/`. |
| Finish a removal stopped part way, from its record | kept | Otherwise a killed invocation leaves a half-removed worktree. |
| Delete branches whose commits are on main, or whose merged or closed pull request holds their tip | kept | Belongs to the merged-or-closed rule. |
| Delete leftover work-snapshots 10 days after first listing, and close restored-branch tasks | kept | Duties of the work-snapshot design, `nn-systems/handoff/handoff-uncommitted-work-snapshots-across-crashes.tool.design.md`; moving them is a change of its own. |
| `--remove-worktree-and-force-delete-its-branch` and `--force-delete-branch` | kept | The first-prompt list prints them beside each entry it lists. |
| `--only-done` at the launchers, the count lines, the dead-registration line | kept | Report only. |

Most of the cleaner's 2,356 lines are the kept duties; the cut removal rules are about 170 lines of its functions and 45 of its docstring, with their tests. Removing more would mean changing what the kept duties protect, which needs a decision of its own.

## 8. Steps that need judgment

The daily job, the one-off move and the cut-down cleaner need none. Three steps do:

1. Whether to carry on a worktree or branch that never had a pull request, or delete it. The agent-session judges each entry the first-prompt list shows it, as now (`nn-systems/handoff/agent-seat-worktrees-and-branches-with-no-pull-request-first-prompt-list.py`).
2. Whether a hand-made scratch folder now in merge-helpers holds anything merge-lane-2 still needs. Once the build merges, its author puts a task on merge-lane-2's task list: merge-lane-2 judges each such folder once, keeps in merge-helpers each one that holds something it still needs, moves every other one into `<root>/merge-lane-2/`, and from then on makes new hand-made scratch there.
3. Whether a program's folder is temporary when its author changes it to write to the root. The author judges: a folder is temporary when what it holds can be made again by doing its work again, as the last column of § 4 shows for each folder there, and it follows § 2's rule of one temp folder for each piece of work.

## 9. Which machines

ned-box only. Everything § 4 moves runs only on ned-box: merge-lane-2 and its programs, and the handoff-supervisor sets `CLAUDE_CODE_TMPDIR` only there. The cut-down `clean-worktrees.py` still runs on both machines. When a program that runs on the Mac first writes to the root, the same job is given a Mac placement, as a launchd job, in `nn-systems/general-tools/scheduled-jobs-on-each-machine.json`, in that program's pull request; the job reads no `/proc`, and where it writes its log there is a deferred decision.

## 10. Guards left out, and how the build goes

**Left out**, each because no failure has been recorded and its harm is work that can be done again: keeping a temp folder that a running process uses or a socket is bound in; keeping the temp folder of an agent-session that crash recovery would resume; keeping the scratch of an open pull request; telling anyone, other than on stderr and in the daily job's log, about a temp folder that fails to delete day after day. Also left out is checking that a deleted folder was really temporary: its harm, the loss of a record put in the root by mistake, is work that cannot be done again, and § 8 step 3's judgment is what prevents it. The worktree removal in § 3 step 3 is not a guard: without it the next review of the same pull request fails every time.

**Build order.** Three pull requests. The tmpfiles rule's new age in `config/ned-box-tmpfiles-tmp-cleanup-rule-ignoring-directory-access-time.conf` is one, since nothing else depends on it. The cut of the cleaner's idle rule, with its test, is another, since it changes only the cleaner. The rest is one pull request, since none of it works without the rest: the daily job and its test; the shared function; the new paths in merge-lane-2's programs and their tests; the new `CLAUDE_CODE_TMPDIR` in `nn-systems/handoff/handoff-supervisor.py`, and the root in place of the old path in `scripts/locate-file-copies-across-machines.py`, which uses it as a search root and a scratch tree; the cut of the cleaner's rule for merge-lane review checkouts, and its test; the deletion of the two retired programs and their tests; the entries in `nn-systems/general-tools/scheduled-jobs-on-each-machine.json`, the daily job's added and the retired job's deleted; the one-off move program; and a test that fails when a tracked file names one of the old places, as one string or as consecutive path parts, `~/.cache/merge-lane-review-worktrees`, `merge-lane-pull-request-reviewer-scratch-directories`, `claude-code-tmp` or `merge-helpers/hr/pr`, so the build finds the callers that name them and the old places do not come back.

**Tests at build time**, since this design states them without having run them: that `git worktree remove --force` run from the repository the `.git` file names removes both the folder and its registration; and that a `claude --resume` given the same `CLAUDE_CODE_TMPDIR` finds its earlier task output. When either fails, the build changes the parts of this design that rely on it before its pull request merges.

## 11. Decisions

1. **Where the root is.** The root is `~/.cache/nedsnodes-temp-folders-by-agent-seat/`. Timeshift's hourly backup of the home directory already skips `~/.cache/**`, so no backup carries the 54 GB, and nobody has to add an exclusion to `/etc/timeshift/timeshift.json`, which agents may not edit.
2. **The `/tmp` rule's age.** The tmpfiles rule for `/tmp` deletes after 7 days instead of 10, so one number holds for both places.
3. **Pattern citations into merge-helpers.** [GHI 2569](https://github.com/nedsnodes/nedsnodes/issues/2569)'s and [GHI 1374](https://github.com/nedsnodes/nedsnodes/issues/1374)'s pattern citations, `hr/pr*/stderr`, `hr/*/log-store/pull-request-head-test-runs/ned-box/*.txt` and `hr/*/tmp/nedschorus-pull-request-head-test-run/*/logs/machine-cpu-and-memory-readings.tsv`, stop opening anything once the folders they match are deleted. The one-off move does not copy the files they match, about 0.43 GB on 2026-11-25, into a records folder, because the measurements those citations served are already written in the two GHI-MDs.
4. **Worktrees whose branch never had a pull request.** The cleaner keeps its owner-stopped rule: once a worktree's owner has stopped and no pull request is open on its branch, the cleaner takes a work-snapshot of its uncommitted files and removes it, keeping its branch, which the first-prompt list then shows its agent-seat. A removal by this rule loses nothing but the worktree's ignored files, which the cleaner names as it discards them, and without the rule the first-prompt list would show the agent-seats about 85 more worktrees a week in all to judge.
