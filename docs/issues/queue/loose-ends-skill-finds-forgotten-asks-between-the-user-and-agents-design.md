# Loose-ends skill: each agent-seat finds what was asked, offered or left open in its conversations that nothing tracks

## Why

The user runs many agent-seats at once and reads each one only now and then. Things that one side asked of the other get lost: an agent waits on a question the user never saw, could not follow, or did not need to be asked; the user asks for something that is acknowledged and never done; a task that says to bring something to the user sits for days, which D10, below, leaves to the task list. Parts of this are caught today, each in one place only: /walk-me-through's "Closing" section makes the agent check one approval-walk for its own unanswered questions and open commitments before the approval-walk closes; /handoff step 1 makes the agent bring its task list up to date, with each question for the user that no approval-walk holds as a task. Nothing reads an agent-seat's conversations for what was lost between the user and its agents; the idle sweep of GHI [Tasks raise themselves when their prerequisites are met, and agent-seats left idle with something to do are woken](https://github.com/nedsnodes/nedsnodes/issues/940) reads a transcript only for a promise or announced action that nothing backs when the agent-seat sits idle. - **D1. What a loose-end is** (2026-10-25, item 14 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`, D12, with item 15.2's three wording fixes, refining the entry approved on 2026-10-23 in its item 4, which replaced the 2026-10-22 and 2026-10-16 definitions). The approved glossary entry: "**loose-end** — something asked, offered or left open that nothing routinely processes: no open task on an agent-seat's task list, open GHI or open pull request holds it in that task's, GHI's or pull request's current text; no session-handoff its successor has not yet read lists it as open; and it is not an unanswered item of an approval-walk still open in a running agent-session. It may concern a task, GHI or pull request, such as a question about a pull request. Work handed to another agent-seat is a loose-end unless a task, GHI or pull request holds it on one side or the other, so the agent-seat that hands it over keeps a task for it until the other agent-seat says it has a task for it. A closed approval-walk's minutes, a cold-read triage, a queue directory and `docs/drafts/` do not count as holding one, because nothing routinely processes them. The plural is loose-ends." The user's reason: "Walks minutes are not operative. There's nothing that is assigned to process them except for perhaps maintenance. Tasks are checked by agents very routinely. I check GHIs. So it needs to be, it's not enough to simply record tasks or items ... They have to be put in some sort of queue that is then looked at to process." A session-handoff holds an item only until its successor has read it; after that, an item there that the successor has neither done nor put in an open task, GHI, pull request or its open approval-walk is a loose-end. The queue-drain that would process the queue directories is GHI [Queue drain procedure — the review process that empties the wiki queue, the pair queue, nn-queue, the drafts directory and the queue-drain-candidate-label issue queue](https://github.com/nedsnodes/nedsnodes/issues/24), open and not built.
