# Handoff-system: fill a task's `branches` field by code, and flag tasks whose branches are gone

This proposal, not yet decided, is item 6 of Question 4, "What should be code", of the cold-read-full-run of `nn-systems/handoff/handoff.system.design.md` on 2026-11-20: `nedlern@ned-box:/home/nedlern/nedsnodes-logs/cold-read-records/handoff.system.design-2026-11-20-6/question-4-what-should-be-code-answer.md`. The queue-drain decides it: if promoted, it becomes a GHI of its own; if declined, this file is removed with the reason in the commit message.

A task records the branches and worktrees it holds in a `branches` field of its metadata, filled by the agent following a reminder, and an abandoned open task keeps its entries off the first-prompt list until someone closes it. A PostToolUse hook on `TaskCreate` could fill the field with the current worktree and branch, and `nn-systems/handoff/agent-seat-worktrees-and-branches-with-no-pull-request-first-prompt-list.py` could flag a task whose listed branches are all merged or deleted, or whose worktrees are gone.
