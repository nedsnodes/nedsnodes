## What is wrong

Two programs write the stop file, `merge-queue-stopped.txt` in the merge program's outputs directory, and each replaces whatever is there: the merge queue program's `stopped()` with `write_text()`, and the merge program, `scripts/merge-lane-pull-request-merge-through-merge-gate-with-stacked-pull-request-retarget.py`, with `write_text()` in its `merge_queue_stopped()` when it exits 3 or 4. No lock orders them, because the merge program holds `merge-program.lock` and the merge queue program holds `merge-batch.lock`, or no lock at all in `start()`. A merge program outlives its merge batch when only the merge batch's process dies, so the two can write at the same moment. When the merge program writes first, the dead-batch reason replaces its reason, and what it said, such as exit 3, "it merged, but a step after the merge, such as main's after-merge test run, did not pass", is left only in that merge's output file, `merge-<pull request>.out` in the merge batches directory, which neither the stop file nor the stopped notice names. merge-lane-2 then handles a dead batch without being told that main's after-merge test run failed. When the merge queue program writes first, the merge program's write replaces the dead-batch reason in the stop file, but the stopped notice already holds the dead-batch reason, so each reason survives in one of the two files.

No record shows this happening, and the merge queue program is not in use yet: on 2026-11-26 ned-box had no directory `/home/nedlern/nedsnodes-logs/seats/merge-lane-2/merge-queue-merge-batches`, the program's default merge batches directory, and no crontab line names the program; `ssh nedlern@ned-box 'ls -d /home/nedlern/nedsnodes-logs/seats/merge-lane-2/merge-queue-merge-batches; crontab -l | grep merge-lane-merge-queue'` checks this again. GHI [Merge queue: when the stop file cannot be written on the dead-batch path, `merge-batch-start` exits 0 and says the stop file was written](https://github.com/nedsnodes/nedsnodes/issues/4979) is a different defect on the same path: a stop file that cannot be written at all.

## What to do

After PR 4988 merges, the agent-seat overall-cleanup, which wrote this program in PR [Merge queue program merges approved lines in order until none is left](https://github.com/nedsnodes/nedsnodes/pull/4893) and wrote PR 4988, fixes this. merge-lane-1 reports that overall-cleanup has a task "Fix GHI 4985" (unverified), for GHI [The merge queue program merges a pull request over a `HOLD-` line appended after it read the queue file and before the merge program merges](https://github.com/nedsnodes/nedsnodes/issues/4985), which changes the same file, so both fixes go together; if overall-cleanup has no such task, this fix is still overall-cleanup's.

The cause is that two writers each replace the stop file. The fix gives the stop file one writer function, in the merge program, which the merge queue program already loads, and has both `stopped()` and `merge_queue_stopped()` call it. The function appends its reason as one line instead of replacing the file; one small write to a file opened for appending on ned-box's local disk does not interleave with another, so the two writers need no shared lock. Every reader, `start()`, `next_merge_may_start()` and the merge program's own check, already quotes the whole file, and `merge-batch-resume` already removes it. `stopped()` also quotes, in its stopped notice, any reason the stop file held before it wrote, so merge-lane-2 reads the merge program's exit 3 in the notice it handles. Codex's round 2 finding suggests creating the file only when it is absent, with `open(path, "x")`, and quoting the reason already there; that also keeps every reason, and the builder may choose it instead. Move the reproduction's case "f8ef37a8b552" into `scripts/merge-lane-merge-queue-approved-lines-merge-in-order-until-none-left-test.py`, asserting that both reasons are in the stop file and in the stopped notice afterwards, and add a test case to `scripts/merge-lane-pull-request-merge-through-merge-gate-with-stacked-pull-request-retarget-test.py` for the writer function appending to a stop file that already exists.
